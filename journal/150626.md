**Daily Project Journal: Seal Online Web Portfolio Data Retrieval**

**Date:** 15 June 2026

Today, I worked on the data retrieval process for my Seal Online web portfolio project. The main objective was to explore how game data can be collected from the Seal Online Fandom Wiki and later stored in a database for use in a web application.

I successfully tested the MediaWiki API by accessing the Seal Online Fandom `api.php` endpoint. The API returned the page content in JSON format, particularly the parsed HTML from the `Monster` page. I learned that the main Monster page works more like an index page, linking to level-based monster pages such as `1-15`, `16-30`, and other level ranges. Therefore, the correct data collection process should start from the index page, fetch each linked level page, parse the monster sections, and then convert the results into structured JSON.

I also converted the JavaScript retrieval script into ES6 module syntax using `import` instead of `require`. During testing, I encountered a TLS/SSL fetch error when using Node.js, so I explored solutions such as checking the Node version, adding request headers, and using Axios instead of the native fetch function. After retrieving the HTML successfully, I confirmed that images do not need to be displayed in the preview because the main purpose is only to collect structured data.

Later, I planned a modular architecture for the data retrieval process. The project was separated into modules such as a Fandom API client, monster parser, repository layer, import service, utility functions, and database configuration. I also discussed the need for database initialization using a schema file for Supabase/PostgreSQL. However, when testing the database initialization script, I encountered a DNS error related to the Supabase database hostname. As a temporary solution, I decided that the database schema can be run manually through the Supabase SQL Editor before running the import script.

Overall, today’s progress helped me understand how to build a more professional data pipeline for the Seal Online portfolio project. The next step is to finalize the database setup, test the monster import process using one level page first, and then expand the importer to collect data from all monster level pages.
